# 02 · 三层元素 (Three-Layer Element Model)

每张幻灯片在视觉上都可以被拆成**互不重叠**的三层。先把页面切成这三层，再下笔画，可以避免 80% 的排版车祸。

## 概览

```
┌─ 控件层 z=100 ───────────────────────────────────┐
│  nav-dots · keyboard-hint · 进度条 · 分享按钮     │
├─ 内容层 z=10 ────────────────────────────────────┤
│  标题 · 副标 · 段落 · 列表 · 公式 · 图片 · 卡片   │
├─ 结构层 z=1 ─────────────────────────────────────┤
│  slide frame · header · footer · grid · gutter    │
├─ 装饰层 z=0 ─────────────────────────────────────┤
│  背景色块 · 模糊球 · 形状 · 渐变 · 噪点 · 网格     │
└──────────────────────────────────────────────────┘
```

## 第 1 层 · 结构层

固定 1280×720 像素基准的「画框」。包含：

- 外框 `.slide` (100vw × 100vh / 100dvh)
- 内部画板 `.slide-inner` (1280×720) — 所有内容都在它内部相对定位
- header 栏（顶部标题区）
- footer 栏（底部页码 / 会议名）
- 主体内容区 `.slide-content`（flex: 1，垂直居中或顶对齐）

**规则**：
- 结构层不可被装饰遮挡，不可见也行但不能"压"内容。
- header / footer 的高度都要算进内容可用空间：`content = 720 - header - footer - padding`。
- footer 若是 `position: absolute; bottom: 30px`，要给 slide-content 一个等大的 padding-bottom 占位。

## 第 2 层 · 内容层

观众眼睛真正在看的东西。**这是页面 60-80% 的高度**。

类型清单：
- 标题（页面主张）：1 个
- 副标 / 引用：0-1 个
- 正文段落 / 列表：1-3 组
- 卡片 / 表格 / 公式：0-2 个
- 配图：0-1 张（**且**必须给图说 alt text）

**规则**：
- 内容元素之间用 gap / margin 而不是绝对定位；这样加一页也能复用。
- 字号：这是投影稿不是屏幕阅读——中文正文**默认 32px、下限 28px**，标题 40-48px，脚注 20-24px（梯度表见 `01-设计令牌.md`）。
- 中英文混排：西文比中文小 1-2px 视觉上才平衡；标题按"中文为主"统一字号。
- 列表项 ≤ 6 条；超过 6 条拆成多页。
- 一页只讲 1 个核心命题（rule of one）。

## 第 3 层 · 装饰层

氛围、节奏、品牌识别。**装饰永远在内容下面**。

常见元素：
- 背景色 / 渐变
- 模糊球（半透明大圆形 + blur）
- 几何形状（圆 / 方 / 多边形 / 网点）
- 噪点纹理 / grid 网格
- 视频背景 / canvas 动画

**规则**：
- **z-index 永远 = 0**，`pointer-events: none`。
- 装饰与内容同色系，否则割裂。
- 每页装饰 ≤ 3 个；超过就开始乱。
- 至少 1 个装饰的角超出视口（不全收），让画面"呼吸"。
- 文字所在的「内容区」上下左右各留 5-10% 的"装饰禁区"。

## 三层关系图

```
内容层 ← 观众视线停留 80% 的时间
   ↑
结构层 ← 固定画框，决定信息密度
   ↑
装饰层 ← 决定情绪基调，氛围感
```

> **设计直觉**：先做白底 + 结构 + 内容（PPT 默认形态），满意后再加装饰层；不要先铺装饰再硬塞内容。

## 翻车自查（每一页出 HTML 前问自己）

1. 内容元素的 getBoundingClientRect 有没有越出 1280×720？
2. footer 是不是被内容的最后一行压住了？
3. 装饰层有没有不小心用 `position: absolute; z-index: 5` 压到内容上？
4. 任意一行中文是否因为 `letter-spacing` 过大导致单字独占一行？
5. 标题换行后，第二行只剩 1-2 个字？（是的话删字 / 调字号）
