# 07 · 中文排印与硬规则

从《中文PPT与网页设计调研笔记》里抽出的、与 HTML 版 PPT 直接相关的**硬数字**。写 deck 时照抄即可，不要凭感觉调。

同目录下另有 `rules_check.js`（仓库根）可自动核验本文大部分条目。

---

## 一、画布与边距

| 项 | 值 |
|---|---|
| 画布 | 1280 × 720（16:9），尺寸用 px 基准 + ScaleController 缩放 |
| 安全边距 | 画布短边的 **4%～6%**（≈ 29–43px） |
| 关键位置 | 重要内容不要放在画面底部，投影现场容易被前排挡住 |

## 二、字号梯度（默认按「投出来能看清」定，不是按屏幕）

```
封面主标题    72 - 96 px
章节 / 大标    56 - 64 px
页面主标题    40 - 48 px
正文          28 - 40 px   默认 32px；小会议室 28，大会议室 36～40
注释 / 脚注   20 - 24 px
```

- 中文正文**不低于 28px**，低于这个数投影即失效。
- 页边距内的辅助文字（标签、页码、footer）最低 20px。
- 最终判据是**投出来走到最远座位看一眼**，公式不如实测。

## 三、字重

- 只用 **400 / 500 / 600 / 700**，同一份 deck 里只取 **2～3 档**。
- **800 / 900 禁用**：中文字笔画密，加粗到 800 以上会糊成黑块。
- 注意坑：`<b>` / `<strong>` 的 UA 样式是 `font-weight: bolder`，父级 700 时会解析成 **900**。
  必须显式封顶：

  ```css
  b, strong { font-weight: 700; }
  ```

## 四、行高

| 类型 | 值 |
|---|---|
| 正文 | 1.5 ～ 1.6 |
| 标题 | 1.15 ～ 1.25 |

## 四之二、标题行数与间距

**标题行数**：默认**单行**。放不下就降字号，**不要插 `<br>` 手撕**。
确实需要两行时最多两行，不许三行；括号里的西文必须和主干同行
（`释放自主智能体 (Agents)`，不是 `释放自主智能体<br>(Agents)`）。

一行大概能放几个汉字 = 可用宽度 ÷ 字号（中文按 1.0em/字，有字间距再留 3~5%）。
**分栏页要按列宽算，不是按内容区整宽算**——这是最常算错的地方。

**括号里的西文要跟主干同行**：`释放自主智能体 (Agents)`，不是 `释放自主智能体<br>(Agents)`；
卡片小标题同理（`提示词时代 (Prompt)`）。但**合并前必须量过**——本仓库实测：

| deck | 卡片内容区宽 | `提示词时代 (Prompt)` 合并后 | 结论 |
|---|---:|---:|---|
| 01 / 02 | 304px | 294 / 302px | ✅ 合并（已改） |
| 05 | 288px | 298px | ❌ 溢出 10px，保留两行 |
| 04 | 280px | 296px | ❌ 溢出 16px，保留两行 |

放不下又不想缩字号时，**两行是正确的选择**，硬并成一行只会让它自然折行、更难看。
（04 想合并得把 28px 降到 26px，低于投影下限，不划算。）

**间距**（按倍数给，别拍脑袋写绝对值）：

| 项 | 值 |
|---|---|
| 标题 → 正文 | **0.4 ~ 0.6 × 标题字号**（56px 标题配 24px） |
| 正文行距 | 1 ~ 1.5 × 正文字号；**正文越小，行距越要放大** |
| 段落间距 | ≈ 行距的 1.3 倍（反过来即「行距 ≈ 段落间距的 75%」最耐看） |
| 列表条目间距 | 0.8 ~ 1.0 × 正文字号 |

- **标题必须显式写 `margin: 0 0 Xpx`**。不写的话 UA 的 `margin: 1em 0` 会叠上来——
  48px 的 `h3` 就是 48px 的幽灵间距，再叠上块内 padding，能凭空多出 140px。
- 内容块在剩余空间里要**上下留白均衡**（差值 ≤ 40px）。只把中间挤紧、底下空一大片，
  跟中间留大洞一样难看。

## 五、字体栈

中文内容必须落在中文系统栈上，否则不同机器渲染出不同字形，已排好的版会散：

```css
--font-sans: system-ui, -apple-system, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Source Han Sans SC",
             "Noto Sans CJK SC", sans-serif;

--font-serif: "Noto Serif SC", "Source Han Serif SC", STSong,
              "Songti SC", SimSun, serif;
```

- CDN 自定义中文字体必须做 `unicode-range` 分片，并带 `font-display: swap`。
- **AI 默认字体禁用**：Inter / Poppins / Roboto / Montserrat / DM Sans / Geist。
  看到 `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto` 这套就要换掉。
- Google Fonts / jsdelivr 在国内常不可达——系统栈不是备选，是主力。

## 六、颜色与对比度

| 场景 | 要求 |
|---|---|
| 正文 | ≥ 4.5:1 |
| 大文本（≥24px，或 ≥18.66px 且加粗） | ≥ 3:1 |
| 白底上的辅助文字 | 不浅于 `#767676` |

- **避免纯黑纯白**：`#000` → `#1A1A1F`，`#fff` → `#F5F5F7`（深色模式给「黑」加一点色相，如 `#12121A`）。
- 白字压浅底是硬伤；浅底上的白字必须有黑色描边才成立（美漫风格常见，见 05）。
- 强调色若既当文字又当底色，压暗到两个方向都达标即可，一次解决双向问题。
  需要保留鲜亮装饰色时，另开 `-ink` 变体专供文字用（见 05 的 `--comic-blue-ink`）。
- 配色：主色 1 种、总色数 ≤ 3；中性打底 + 高饱和做强调。

## 七、中文排印

| 规则 | 做法 |
|---|---|
| 引号 | 横排用 `“”` 和 `‘’`，**不用** `「」『』`（GB/T 15834-2011） |
| 斜体 | 中文没有真斜体，浏览器会合成伪斜体。**禁止** `font-style: italic`，改用加粗 / 颜色 / `text-emphasis` |
| 自动换行 | `word-break: normal` + `overflow-wrap: break-word`；只有长 URL / 长 ID 才用 `break-all` |
| 字间距 | 只加在标题上，**正文不要加** |
| 断行优化 | 标题 `text-wrap: balance`，正文 `text-wrap: pretty` |
| 中英混排 | 西文比中文小 1–2px 视觉上才平衡 |

## 八、动效与导出

- 动效一律包进 `@media (prefers-reduced-motion: no-preference)`。
- 导出 PDF：加 `print-color-adjust: exact`；`@page { size: 1280px 720px; margin: 0 }`；勾 Background graphics；用 Chromium。
- **导出前先把所有入场动画强制置为终态**，否则会截到 `opacity: 0` 的空页。

## 九、AI 生成物的雷区（自检用）

看到下面这些，基本可以判定是「没过脑子的 AI 稿」：

- 通篇 Inter / Poppins / Roboto
- 清一色 `rounded-2xl` 圆角卡片
- 三段式「卡片三兄弟」排版（三个等宽卡片横排）
- `opacity: 0` + `translateY(20px)` + `ease-in-out` 三件套动效
- 蓝紫渐变（色相 200°–290°）
- 居中的 eyebrow + 标题 + 副标题堆叠
- 标题没加 `text-wrap: balance`

## 十、自动化核验

仓库根的 `rules_check.js` 把上面大部分条目做成了自动检查：

```bash
node rules_check.js                    # 扫 references/decks/ 下全部 deck
node rules_check.js --dir outputs      # 扫指定目录
```

检查项：无中文栈 / AI 默认字体 / 字重 >700 / 中文斜体 / 字号过小 / 行高偏小 /
标题行高过大 / 正文字间距 / 纯黑文字 / 浅底纯白字 / 对比度不足 / 直角引号 /
`word-break: break-all` / 标题未加 balance / 文本被容器裁切。

**已知豁免**（不是漏检）：

- 有硬描边（`text-shadow` 模糊半径为 0 且偏移 ≥2px，或 `-webkit-text-stroke`）的
  美漫描边字不计对比度——WCAG 算法算不出描边效果。柔和阴影不算。
- inline 元素的 `line-height` 不决定行盒高度（由父级 strut 决定），跳过。
- 单行文本不受行高下限约束。
- 标签 / 副标题 / 页码 / 眉题这类非正文角色，字间距不受正文规则约束。
