自揭老底：
我到底用AI做了哪些事儿

从 Prompt 到 Skill，再到养龙虾

一个有趣的招聘标准

思考

看到一位 Kimi 的 PM 在招人，他提到了一个令人印象深刻的重点：

"招人需要看你做了什么工作，以及你的 Token 消耗量 怎么样。"

这引发了一个问题：你的 Token 消耗量，真的反映出你对 AI 的有效利用了吗？

我用 AI 的三个阶段

01

提示词时代
(Prompt)

一问一答，尝试寻找神级指令。探索 AI 的边界与局限。
02

技能时代
(Skill)

构建工作流。结合上下文，把 AI 封装成解决特定问题的工具。
03

养龙虾时代
(Agents)

自主智能体。给定目标与环境，让 AI 自主规划、执行与反思。

阶段一：提示词 (Prompt)

试图用一句话解决所有问题

  • 交互模式： 一问一答，直接向大模型索要结果。
  • 典型场景： “帮我写一篇1000字的爆款文章”、“帮我生成一个标题”。
  • 真实体感： 写了无数的 Prompt，查阅了各种技巧，但出来的结果总觉得“差点意思”。
  • 产出质量： 逻辑往往不受控，AI 的发挥具有很强的随机性。

核心痛点

Prompt 并不是万能的

为什么大模型写不出你心里的那篇文章？因为 缺少上下文 (Context)。

单靠指令是不够的。AI 不知道你的业务背景，不知道你的受众，也不知道你之前试错的过程。

结论： 我们需要把隐性知识和业务流程，结构化地喂给 AI。

阶段二：技能 (Skill)

引入工作流 (Workflow)

  • 核心转变： 从“对话框许愿” 走向 “工程化拆解”。
  • 运作方式： 将任务拆分成多个节点，结合特定的上下文，固化为可复用的“技能”。
  • 工具组合： 开始大量使用 Coze、Dify 等平台编排工作流。
  • 优势： 结果变得可控、稳定，真正可以作为生产力工具。

动手实践：构建实用工具

个人提效

沉浸式翻译器

不再只是简单的中英互译。

要求 AI 提供翻译的思考过程，分析语境，甚至进行多语言的精准适配。

团队赋能

SEO 关键词助手

为团队内部开发的专属工具。

结合公司实际业务场景，将复杂的 SEO 调研流程封装成一个任何人都能用的一键技能。

Workflow
的局限性

虽然“技能”和“工作流”解决了稳定性问题，但它们是 线性且静态的。

  • 遇到预设之外的异常，流程就会中断。
  • 无法根据实时反馈自我调整。
  • 仍然需要人类去“点击运行”或做大量的前置输入。

阶段三：养龙虾时代

自主智能体 (Autonomous Agents)

  • 为什么叫“养龙虾”？ 因为你不再需要手把手教它每一步。
  • 你的角色： 养殖者。提供环境、提供工具（鱼饵/水质）。
  • AI 的角色： 自主生物。你给它一个终极目标，它自己去规划路径、调用工具、评估结果、反思修正。

养虾实践：自动化内容生产

1

RSS 抓取

Agent 自动订阅并抓取全网最新资讯源，进行初步数据清洗。

2

自主思考生成

AI 自主评估信息价值，根据设定好的风格生成高质量文章。

3

自动发布

通过接口，将排版好的内容自动分发到指定平台，全程无人干预。

如何养好“龙虾”？

给足空间与工具

Agent 需要联网搜索、读写文件、甚至调用外部 API 的能力。

工具越丰富，它能解决的问题维度就越高。

清晰的边界与目标

不能只说“帮我赚钱”，而是给出明确指令，比如“每天抓取新闻并总结”。

设定好纠错机制，防止它在死胡同里无限循环消耗 Token。

代价与真正的价值

不可避免的代价

在这个阶段，你会发现：

Token 的消耗量
开始疯狂飙升。

真正的独立价值

Agent 在后台不断地思考、调用 API、失败重试、反思修正。

不再是你推一下它走一步，
而是它自己在为你打工。

回到最初的问题

Token 消耗量代表了什么？

它代表了你从“把AI当百科”
到“把AI当员工”的转变深度。

不要只停留在对话框里

去构建工作流，去释放智能体。
