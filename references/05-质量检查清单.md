# 05 · 质量检查清单 (QA Checklist)

每一份 HTML 出炉后**必跑**这 6 类检查 + 2 个自动脚本。任何一项不通过就回去改，不要交付"看上去差不多"的版本。

> 现状：`references/decks/` 下 10 份 deck / 137 页，几何与排印两项均已 0 问题。
> 改动模板后务必两个脚本都重跑——改字号、换行高、换字体栈都可能让原本刚好的页面长高几像素。

## 1. 越界检测（必须 0 越界）

工具：Playwright + `getBoundingClientRect`。

```js
const slides = document.querySelectorAll('.slide-inner');
slides.forEach((s, i) => {
  const r = s.getBoundingClientRect();
  if (r.width > 1280 || r.height > 720) console.log(`P${i+1} 帧越界`, r);
  s.querySelectorAll('*').forEach(el => {
    const er = el.getBoundingClientRect();
    if (er.bottom > r.bottom + 2 || er.right > r.right + 2)
      console.log(`P${i+1} 元素越界`, el, er);
  });
});
```

**已修的踩坑**（参考）：
- 03 P15 公式页两个 `academic-box` 叠起来超过 720 → 缩 box 间距 + 缩公式 padding-bottom
- 06 P12 红黑对开面板字数太多 → 减小内边距 + 缩小主标题字号
- 07 P4/P6 列表最后一项压 footer → 缩 list margin-bottom + 缩 header margin-bottom
- 公式 `formula-container` 用 `overflow-x: auto` 截断下标 → 改 `overflow: visible` + 加 `padding-bottom: 10-14px`

## 2. 截断检测（必须 0 截断）

任意 `text-overflow: ellipsis`、`-webkit-line-clamp`、`overflow: hidden` 都要审视是否合理。

- 装饰图标 + placeholder 图：可以截
- 任何带正文的元素：不可以截
- 长文列表：拆页，不要 `line-clamp: 3`

## 3. 公式渲染（学术 / 教学 deck 必跑）

```js
const math = document.querySelectorAll('math');
math.forEach(m => {
  const r = m.getBoundingClientRect();
  if (r.width === 0) console.warn('公式未渲染', m);
  if (r.height < 10) console.warn('公式高度异常', m);
});
```

如果用了 MathML 之外的方式（KaTeX / MathJax）还要：
- 确认 CSS `.katex, .MathJax` 都被 `.slide-inner` 包裹
- 公式行间距 ≥ 1.2

## 4. 字体兜底（断网 / 字体加载失败时）

```js
await document.fonts.ready;
const samples = ['.slide-title', '.text-body', '.quote-body'];
samples.forEach(sel => {
  const el = document.querySelector(sel);
  if (!el) return;
  const cs = getComputedStyle(el);
  // 字体被 fallback 时 family 列表里会包含 serif/sans-serif/monospace
  // 粗略判断：检查实际宽度
  console.log(sel, cs.fontFamily, el.getBoundingClientRect().width);
});
```

更稳：开 DevTools → Network → Offline → 刷新，看页面是否还有方块 / 字体坍塌。

## 5. 链接 / 交互

- 任意 `<a>` 都要 `target="_blank"` + `rel="noopener noreferrer"`
- nav-dots 点击要能跳到对应 slide
- 键盘 ↑↓←→ 都要能翻页（按主流 deck 都做了）
- 内容元素 `contenteditable="true"` —— 改字后要可保存（用 `<details>` 教学法即可，不必真存）

## 6. 移动端退路

把窗口缩到 375px 宽，刷新页面：
- 文字不重叠
- nav-dots 自动消失
- slide-inner 高度自适应（不强制 720）
- 字体不被强制缩到看不见

## 7. 分栏陷阱（.layout-split 专项）

「左右分栏变上下堆叠」是本仓库踩过的最大的坑，**7 份滚动式 deck 全中招**，
而且症状会伪装成别的问题：标题错位、标题莫名折行、正文之间出现大空白。

**根因**：`.layout-split` 永远和 `.slide-content` 挂在同一个元素上
（`<div class="slide-content layout-split">`）。`.layout-split` 没写 `flex-direction`，
同优先级下被 `.slide-content` 的 `flex-direction: column` 赢了，于是所有"左右分栏"页
全渲染成竖排。

**修法**（已落在 7 份模板上）：

```css
/* 用 grid，别用 flex：flex:1 1 0% 分不均，grid 1fr 1fr 才是真的一半 */
.layout-split {
    display: grid;
    grid-template-columns: 1fr 1fr;
    gap: <原值>;            /* 各 deck 不同：40 / 50 / 60 / 80 */
    align-items: <原值>;    /* center 或 flex-start，保持原设计 */
    height: 100%;
}
.layout-split > * { min-width: 0; }   /* 不加的话长单词会把列撑开，分栏失效 */
```

- **为什么不是 flex**：容器 1168 + gap 40 时，`flex: 1 1 0%` 实际分出 **518 / 610**
  （不是 564 / 564），差的这 46px 正好把一个 554px 的标题挤到折行。
  `grid-template-columns: 1fr 1fr` 干干净净是 564 / 564。
- **怎么发现**：量分栏容器前两个子块的相对位置，`kids[1].left >= kids[0].right` 才是横排。
  只看 CSS 里的 `display: flex` 会漏掉——它确实是 flex，只是方向错了。

**连锁症状**：分栏失效后左列宽度变成整幅 1168px，宽到不会折行，看着"没问题"；
但一旦分栏修好、列宽缩回 564px，之前没折行的标题就折了。
所以**分栏修完必须把所有标题的行数重测一遍**（见 ④）。

## 自动脚本一：`qa_check.js`（几何）

```bash
npm install playwright-core     # 只需装一次
node qa_check.js your-deck.html            # 终端打印越界 / 截断清单 + JSON
node qa_check.js your-deck.html --shots    # 额外逐页截图到 .qa-shots/<deck 名>/
node qa_check.js --all                     # 批量跑本仓库所有 deck
node qa_check.js --all --offline           # 掐断 CDN，按系统字体回退测
```

退出码 0 = 全部通过，非 0 = 有问题的 deck 数。浏览器路径可用 `CHROME_PATH` 指定。

它会自动识别两种 deck 形态：

- **滚动式**（有 `.slide-inner`）：注入 `scroll-snap-type:none` + `transform:none`，把所有页一次性展开成 1:1 后逐帧测。
- **单页式**（只有 `.slide`，`.active` 切换）：**逐页把 `.active` 切过去再测当前帧**——千万别一次性 `display:block` 展开所有页，那样页面会互相重叠，报出一堆假越界。

## 标题排版六查（两个脚本都覆盖不到，要单独看）

`qa_check` 管溢出、`rules_check` 管排印，但**标题好不好看**这两者都不管。补查六项：

**① 孤字** —— 标题折行后末行只剩 1-2 个字，是中文排版最刺眼的问题。

```js
const linesOf = el => {                      // 逐字符建 Range，按 rect.top 归组
  const w = document.createTreeWalker(el, NodeFilter.SHOW_TEXT);
  const rows = []; let n;
  while ((n = w.nextNode())) {
    const rng = document.createRange();
    for (let i = 0; i < n.textContent.length; i++) {
      rng.setStart(n, i); rng.setEnd(n, i + 1);
      const r = rng.getBoundingClientRect();
      rows.push({ ch: n.textContent[i], top: Math.round(r.top), l: r.left, r: r.right });
    }
  }
  rows.sort((a, b) => a.top - b.top || a.l - b.l);
  const lines = []; let cur = null;
  for (const x of rows) {
    if (!cur || Math.abs(x.top - cur.top) > 4) { cur = { ...x, s: '' }; lines.push(cur); }
    else { cur.l = Math.min(cur.l, x.l); cur.r = Math.max(cur.r, x.r); }
    cur.s += x.ch;
  }
  return lines;
};
// 末行 ≤2 字，或末行宽度 < 整块宽度的 12%  ->  孤字
```

- **旋转文字会让这个方法失效**：倾斜标题里每个字的 `top` 都不同，会被切成十几"行"。
  遇到 `transform: rotate/skew` 的标题，改成按旋转后的**法向投影**分组：
  `d = -sinθ·cx + cosθ·cy`（θ 取自 `matrix(a,b,…)` 的 `atan2(b,a)`），再按 `d` 归组。

**② 安全边距** —— 内容到画布四边 ≥ 短边的 4%（1280×720 下 ≈ 29px）。
别拿 `.slide-inner` 当画布：有的 deck 内层框只有 1000×504，真正的 1280 舞台在外层，
按内层量会误报"边距 0"。判据是**宽 1180~1400 且高 600~800** 的那层。
同理，终端窗口标题条这类**模拟 UI 装饰**里的文字不套页面边距规则。

**③ 纵向位置一致性** —— 同一 deck 的正文页标题应落在同一高度，
翻页时标题忽上忽下会有"变形感"。取各页标题 `top` 的中位数，偏离 >24px 的单独看。
**封面页和致谢页要排除**，它们本来就该居中另排。

**④ 标题行数 —— 短标题必须单行，禁止 `<br>` 手撕。** 这是改版时翻车最多的一条：
10 份模板里一共挖出 18 处硬编码换行，全是 6~9 个字的短标题被拆成两行。

规则：

- 页面主标题**默认单行**；实在放不下才允许两行，**不允许三行**。
- 放不下时**降字号**，不是插 `<br>`。可用宽度 ÷ 字号 ≈ 一行能放几个汉字
  （中文按 1.0em/字估，标题有字间距再留 3~5% 余量）。
- 括号里的西文要和主干**同行**：`释放自主智能体 (Agents)` 不能拆成
  `释放自主智能体<br>(Agents)`——它只是一个补充说明，不是第二层意思。

量法：把标题设成 `width: max-content` 量一次，跟容器可用宽度比。
分栏页尤其要小心：可用宽度是**分栏后的列宽**，不是整个内容区。
（01 P2 的 `一个有趣的招聘标准` 9 字 × 56px ≈ 580px，列宽只有 564px，
于是折行；降到 48px 后 508px，单行。）

卡片小标题里被 `<br>` 拆开的括号西文（`提示词时代<br>(Prompt)`）同样该合并，
但**合并前先量卡片内容区宽度**——本仓库 04/05 的卡片只有 280/288px，合并后要 296/298px，
硬并会溢出。放不下时保留两行是对的，详细数字见 `07-中文排印与硬规则.md`「四之二」。

**⑤ 标题→正文的间距，和「垂直均衡」。** 两头都要看，只看一头会顾此失彼：

| 项 | 经验值 |
|---|---|
| 标题底 → 正文块顶 | **0.4 ~ 0.6 倍标题字号**（56px 标题配 24px） |
| 内容区上留白 vs 下留白 | 差值 ≤ 40px；差太大就像"没排完" |

- 判据要量**最外层内容块**的顶边。量到卡片内部的 `<p>` 会虚高几百 px。
- 只把中间挤紧、底下却空 190px，跟中间留大洞一样难看——改完必须回头看下留白。
- 两个高频成因：
  1. **UA 标题默认外边距叠加**。`h3` 的 UA 样式是 `margin: 1em 0`，48px 字号就是 48px，
     再叠上显式 margin 和块内 padding，凭空多出 140px。标题一律写 `margin: 0 0 Xpx`。
  2. **`justify-content: center` 被改没了**。07 的 P4/P6/P9 改版时丢了这条内联样式，
     内容顶部对齐，底部空出 191px——而同 deck 其它页都是上下各留 62px。
     改版后拿"上间距 / 下留白"跟兄弟页对一下，能立刻发现。

**⑥ 形状容器装字 —— 看内接安全区，不是外接框。** 用了 `clip-path` 的星形、爆炸框、
对话框这类容器，字被裁掉不会触发任何溢出告警，`qa_check` 也测不出来。

| 形状 | 内接矩形安全区（占外接框） |
|---|---|
| 五角星 | **30% × 30%** |
| 12 角爆炸框（内径 0.88） | 62% × 62% |
| 粗描边硬边徽章 | ≈ 92% × 92% |

五角星看着很大，真正装得下字的只有中间那一小块；**成句（>6 汉字）永远塞不进星形**——
实测 `打破对话框的边界！` 要星形宽到 1564px 才装得下。所以：

- **短标签**（≤6 拉丁字符 / ≤3 汉字）→ 多角爆炸框，角多肚子大
- **成句** → 硬边徽章 / 色块高亮，别硬撑星形
- 装饰性星形就不写字，纯当图形用

量法：逐字符建 `Range` 取 rect，把 rect 的**四个角**都做一次"点在多边形内"
判定（射线法）；再从中位线向外搜最大内接矩形，得到上表的安全区。

> 上面三项的现成脚本在 `.workbuddy-ai/tools/`：`probe-layout.js`（④⑤，含标题行数、
> 上下留白）、`shape-fit.js`（⑥）、`probe-page.js`（单页元素树）。
> 这些是开发工具，不随 skill 交付。

## 自动脚本二：`rules_check.js`（中文排印）

几何过关不代表能看。字体栈、字重、对比度、行高、引号这些要单独跑：

```bash
node rules_check.js                    # 扫 references/decks/ 下全部 deck
node rules_check.js --dir outputs      # 扫指定目录
node rules_check.js --json > r.json    # 只输出 JSON
```

检查项：无中文栈 / AI 默认字体 / 字重 >700 / 中文斜体 / 字号过小 / 行高偏小 /
标题行高过大 / 正文字间距 / 纯黑文字 / 浅底纯白字 / 对比度不足 / 直角引号 /
`word-break: break-all` / 标题未加 balance / 文本被容器裁切。

默认掐断外部请求按系统字体测量。已知豁免（不是漏检）见 `07-中文排印与硬规则.md`。

## 两个脚本的共同坑

1. **测量前必须等 `document.fonts.ready`**。CDN 字体到达前后字宽不同，早测会得到假结果——
   实测同一份 deck 会一会儿 0 页问题、一会儿 11 页，纯粹是因为字体到达时机不同。
2. **优先按离线（系统字体）结果验收**。Google Fonts / jsdelivr 在国内常不可达，
   客户打开时大概率就是回退状态，那个状态过不了就是真的过不了。
3. 装饰层（`bg- / deco / shape / blob / pattern / watermark / noise / grid-bg / canvas / matrix`）
   在 qa_check 里被刻意跳过，别当成漏检。
4. **别用「移动元素」做扫光 / 流光装饰**。典型写法是父容器 `overflow: hidden` +
   子元素 `left: -100% → 200%` 跑 `infinite` 动画。元素跑到右边时，父容器的
   `scrollWidth` 会被撑到 2 倍以上，检测脚本测到动画的哪一帧，结果就不同——
   离线（加载快，落在动画前段）全绿、在线（加载慢，落在后段）报 11 页。
   
   02 的 `.glass-panel::before` 就是这么写的，已改成**元素贴住面板、只让渐变移动**：

   ```css
   /* 反面：元素位移 -> scrollWidth 随相位漂移 */
   .glass-panel::before { left: -100%; width: 50%; animation: shine 8s infinite; }
   @keyframes shine { 0%,60% { left: -100%; } 100% { left: 200%; } }

   /* 正面：inset:0 贴合，背景渐变自己走 */
   .glass-panel::before {
     inset: 0; background-image: linear-gradient(100deg, transparent 38%, #fff8 50%, transparent 62%);
     background-repeat: no-repeat; background-size: 50% 100%;
     animation: shine 8s infinite;
   }
   @keyframes shine { 0%,60% { background-position-x: -200%; } 100% { background-position-x: 300%; } }
   ```

   qa_check 现在也会给伪元素强制 `animation: none`，把这类相位漂移压掉。
   但**根因在 CSS 里**，脚本只是兜底。

## 自检 Step by Step

| 步骤 | 检查项 | 通过标准 |
|---|---|---|
| 1 | 1280×720 截图 | 17 张图无越界 |
| 2 | 文本扫描 | 无 `**` `#` 残留 |
| 3 | 公式容器 | 高度 ≥ 字号 1.2x |
| 4 | 字号梯度 | 至少 3 档 |
| 5 | 装饰数量 | 每页 ≤ 3 个 |
| 6 | footer 高度 | 不被内容压住 |

> 一个 deck 跑完 1-3 全过 = 可以交付；4-6 是体感分，差一两项可接受。
