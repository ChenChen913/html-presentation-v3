今天刷视频的时候，看到一个好像是 Kimi 的 PM 在网上拍视频招人。他说了一个令我印象比较深的重点：他招人需要看你做了什么工作，以及你的 Token 消耗量怎么样。

所以就有了这篇文章。我想来仔细盘点一下，我到底用 AI 做了啥。

我最开始切入 AI 的时候，主要有两个方向：

1. AI 提示词（Prompt）
   我看到别人写了很多关于如何使用 AI 的提示词，读这些内容会有一种被打开思路的感觉。

2. AI 作图
   观察别人用 AI 生成图片的效果，以及他们生图时使用的提示词，这些内容非常容易让人眼前一亮。

这两个方向算是我在 AI 领域的启蒙。关于提示词，我之前也写过相关的文章，链接如下：【】

从这两个方向往后，我开始尝试用 AI 做一些 HTML 网页。我刚才让我的小龙虾帮我总结了一下，发现目前已经累计生成了 140 多个 HTML 网页。

虽然这其中大部分都是没用的尝试，但也有几类我觉得非常有价值的产物：
1. 桌面时钟（本质上是一个时钟网页）
2. 医院住院系统（单个网页原型）
3. 血压记录工具

我觉得有用的这几类网页，每一类都经过了多次迭代。我会经常和 AI 探讨如何优化这些页面，并不断提出具体的需求。

以那个“医院住院系统”的单页为例，我跟 AI 深度交流后，一共产生了十多个版本的网页文件。通过一次次的迭代更改，看着这儿不太行、那儿需要调，前后调整了十好几次。类似地，那个时钟项目也经历了非常多次的迭代，期间我和 Claude、Gemini 等模型都做过不少沟通交流。

然后我就从用 AI vibe Coding 做单个的网页，慢慢过渡到了用 AI vibe Coding 做小项目。

其实我用 AI vibe Coding 做小项目，也是基于我之前的一些 HTML 网页。

比如关于这个数据卡片，我之前喜欢用单个网页去复刻我看到的一些比较好看的设计，然后再通过截图的方式保存下来。

我后来就把这种生成数据卡片的过程转化为了一个项目，也就是和 AI vibe Coding 一起做出一个可以生成并下载数据卡片的工具。

因为我个人可能有点强迫症，所以我和 AI 合作做了至少两个这种生成数据卡片的小项目。

关于项目开发，我之前还做过一个医药管理系统。这个项目的初衷其实很简单，就是想给家里人自用。当时听到家里人随口说了一句“某个药快过期了”，这句不起眼的话激起了我的灵感。

我想着可以用 AI 开发一个线上的“电子药箱”，把家里买的各种药品记录下来，包括：使用说明、保质期和药品分类等等。

当药品快过期或者快吃完的时候，系统会自动发出提醒。我后来真的把这个项目做出来了，虽然因为经济压力没有正式上线，但整个开发过程感觉还是挺好的。

其实说到做项目，就不得不说我做 AI 项目的工具。

我记得我做的第一个 AI 项目，应该就是我说的那个医药管理系统。当时我用的 AI IDE 是叫 Kiro，这个工具有一个模式叫做 Spec 模式，是我第一次接触这个模式，之前接触是 Plan 模式。

关于做 AI 项目的工具，后来也陆续接触到了 ClaudeCode 和 Trae。其实我做项目，感觉用的最多的还是 ClaudeCode 和 Trae 这两个东西。

后来也做过一个微信小程序，全程都是 AI 干预的。为此我还写过一篇文章，文章链接【】

其实在 AI 火起来之前，如果你去面试工作，HR 可能会问你在做项目时遇到了什么困难，又是如何解决的。但现在是 AI 时代，如果你问我类似的问题，我会说用 AI 做项目遇到的最大困难主要有两点：

1. 资金与 Token 问题
   因为缺钱，没能用上最顶尖的大模型。或者说我投入的那点钱，用顶尖模型一会儿就消耗完了，额度很快就会用光。

2. 设备问题
   我目前使用的是 Windows 系统电脑，非常想买一台苹果电脑，尝试利用 Mac 系统重新搭建一下我的 AI 生态。

如果你问我用 AI 做项目有没有什么技巧，其实也没有什么技巧。最好的技巧就是用上最好的模型，仅此而已。

对了，我还忘记说了，在用 AI 做项目的同时，我也用了很多的 skill。因为我接触了 ClaudeCode，skill 是肯定要接触的。

我用了很多 skill，同时也做了很多 skill，有一些具体的体会。在使用这些 skill 的时候，我最大的体会也很简单粗暴：如果你不是用最好的模型去驱动这些 skill，你根本无法把这些 skill 的功能发挥到极致。

我觉得：
1. 如果是一个顶尖模型搭配上 agent，它甚至不需要 skill 就能很好地完成一些任务。
2. 如果是一个比较弱的模型，即便搭配上了某些 skill，它执行任务的能力也非常让人着急。

但是不得不说，这个 skill 也不能说一点用都没有。对于弱模型来说，不能说完全没用。虽然我说这个 skill 需要搭配比较顶尖的大模型，才能发挥出它的效果。但很多人根本不舍得花钱去用这么好的顶尖模型，就会选择国内的模型，因为国内的模型比较便宜，其实它们的能力或者在某些排行榜上的评分也比较高，也凑合能用。

所以我想补充一点，其实这个 skill 对人来说是一种思维的开阔。

1. 类比初期接触 AI 的感受
   我用 skill 的感觉，就像最开始接触 AI 时看到那些新奇的提示词一样。当我看到大佬们写出的非常有条理、结构化、具体详细且专业的提示词时，都会眼前一亮，感叹提示词原来还可以这样写。

2. 对 AI 用法的重新认知
   现在看到 skill 之后，我同样会眼前一亮。原来还能给 AI 指定这样的用法，还能告诉 AI 这样做，这本身就是一种思维的开阔。

我觉得相对于完成任务来说，它更大的一个特点是真的开阔了人的思维。

我用 skill 时间长了，会改变我看待事物的一些角度。

之前我看待某一个任务，比如我最近在做的和数据分析有关的一个 skill（具体来说就是想让 AI 获取某个学校的考研复试名单、拟录取名单以及考研细则，再进行数据清洗和分析，最后产出数据报告），如果思维过程比较短，会把这个任务想象得非常简单：让 AI 获取信息，然后分析就行了。

但我用 skill 时间长了之后，就会把任务拆解得非常细致。我的思考过程变得更精细化、模块化，倾向于用多个 skill 去组合协助执行任务：

1. 获取信息阶段：调用网页搜索类的 skill，获取信息并下载到本地。
2. 数据处理阶段：将信息转化为 JSON 数据，或者进行向量化处理。
3. 数据分析阶段：调用数据分析类的 skill，分析名单中的最高分、最低分以及单科分数等。
4. 结果展示阶段：
   (a) 将分析结果以 HTML 网页的形式展示出来。
   (b) 产出一份 Word 文档或者 Markdown 格式的数据分析报告。

它真的能让人把任务原子化、精细化，这是我用 skill 一个比较深的感受。

我最近对 skill 还有一个感受，就是它可以作为人的一个辅助记忆系统。

比如我最近在用飞书，它已经开放了 CLI，我可以通过 ClaudeCode 去获取飞书上的文档信息。但我发现 ClaudeCode 在获取信息的过程中非常麻烦，踩了很多坑，终端也报了很多错，过程非常漫长。

我就在想，执行任务这么费劲，还不如我手动执行，几分钟就完成了。交给 ClaudeCode 做可能需要十分钟，这是一个非常恐怖的时长。

这时候，在 AI 执行完任务后，我就可以告诉它：
1. 总结在执行任务过程中遇到的困难、踩过的坑、犯过的错以及绕的弯子。
2. 把这些东西整理一下，做成一个 skill。

这样下次再获取飞书文档的时候，就直接执行这个 skill。我可以把 skill 当作我的、或者说当作 AI 的一个记忆系统，让它长记性，不要再犯同样的错误。

这是我觉得做 skill 的另外一个优势。

我觉得安装和使用 skill 的过程，本身也是一个学习的过程。

现在 GitHub 上有很多非常优秀的 skill 系统。往往这些官方或者一些大佬会提供一套很全面的 skill，它们可能覆盖你工作的大部分内容。但这也就引发了另一个问题：优秀的 skill 太多了，容易让人产生选择困难症。

如果全部安装，skill 肯定会显得非常臃肿；但如果一个都不装，又有点固步自封的感觉。所以我一直在想，大佬们的 skill 肯定要借鉴，但不能盲目地大量安装。

我的原则是：
1. 按需安装：找到适合自己的 skill。
2. 精选功能：比如某些官方出的 skill 很优秀，但我只挑自己能用到的，像操作 PDF、Word 或 Excel 文档这类工具，我就把它加进来安装一下。
3. 前端类：如果是前端类的 skill，我也会下载。
4. 及时止损：对于很多下载下来就只能“吃灰”、根本用不到的 skill，我就干脆不下。

如果没有适合自己的，或者现有的 skill 根本不能适配我当前的工作，那我就自己做一个。

前面也提到过，我特别喜欢数据卡片。后期我也确实做了一些生成数据卡片的 skill，效果还行。对我来说，主要是享受制作 skill 的这个过程。

我自己做了很多 skill，其中我比较得意的有几个：

1. 知识提取类 skill
   (a) 通过让 AI 向用户提问，挖掘用户的一些认知和观点
   (b) 让用户认识到自己的不足
2. 健康管理类 skill
   该 skill 包含四条线：
   (a) 运动管理
   (b) 健身管理
   (c) 数据分析
   (d) 中医管理

虽然市面上健康管理类的 skill 也有，但我的这个应该是第一个结合了中医的 skill。

你去做这些 skill 的时候，做出来的那一刻，或者说不断和 AI 去打磨的过程，真的非常享受。

我觉得做单个网页、做 skill 以及做项目，这三者之间应该是有联系的。它们代表了任务的不同复杂度：

1. 做网页代表着简单。
2. 做 skill 代表着任务处于中等水平，既不简单也不算太难。
3. 做项目则意味着需要稍微上一点难度。

我在做这三个东西的时候常会思考，如果一个网页变得特别臃肿（比如代码写到了上千行），我就会考虑把它做成一个项目，看看稳定性是否会更好。

同样，在做 skill 的时候我也在想：既然一个 skill 需要这么多附属文件，或者在不用上优质 AI 大模型的情况下作用发挥不到位，那么此时我也会考虑将其扩展成一个小项目。

所以我觉得这三者是相通的。

后来我发现不止一个博主在强调，技术的稳定性是非常重要的。

实现一个任务有很多种方法（可以做成 skill，也可以做成项目），但不管用什么方法，一定要保证方案的稳定性。所以有几个博主的观点是：能用脚本就不要用 Agent。此处的“脚本”泛指 Python 程序，也就是说，能用程序解决的事情，就不要动用 AI Agent 去处理。

这其实就是一个简单的道理：杀鸡焉用宰牛刀。

这里有一个具体的例子，就是处理 Markdown 文件中“中英文之间没有空格”的问题。如果你交给 AI 去改，告诉它要在文档的中英文之间加上空格，如果这篇文章包含大量的文字，交给 AI 处理会非常消耗 token。

但如果我写了一个 Python 程序去加空格，那么不管文章有多长，用程序处理肯定比用 AI 大模型要高效得多。

这个例子告诉我，新技术、新概念不一定就是最好的。有时候，那些传统的技术也能够带来更高效的结果。


我再说一说“养龙虾”这个事。这个“龙虾”指的就是 OpenClaw，这也是我最近刚有的一个想法。

如果你用大厂做的 Agent（比如国内的 Trae 这种），我觉得会受到一些限制：
1. 大模型排队：使用时往往需要排队等待。
2. 任务监视：你在做任务时，它可能会在背后监视任务的合法性。

相比之下，使用 OpenClaw（小龙虾）就没有这些限制：
1. 无需排队：做任务时不需要排队，只要花钱买额度，然后调用 API 就可以了。
2. 自由度更高：它的运行逻辑和小龙虾一样，直接通过 API 调用。

其实我用 OpenClaw 的时候，并没有觉得它有什么特别惊艳的地方。它确实是用一些已经存在的技术，组装成了一个看起来相对厉害的东西。

我觉得 OpenClaw 能做的任务，其实 ClaudeCode 都能做，所以没必要去神化 OpenClaw 这个东西。

然后聊一聊我最近对于 AI 有了一个更新的认识，就是“记忆系统”。

之前有 AI 博主发过类似的视频，呼吁大家去做一个属于自己的 AI 记忆系统，把自己的认知观点、行为习惯等通过 AI 保存记录下来，从而便于后期使用，或者让 AI 更懂你，做一个“数字化分身”。

大概就是这么一个道理。目前来看，我觉得做一个记忆系统真的太重要了。

最近 GitHub 上有一个比较火的项目叫做“同事 skill”。

也就是说，当一些人离职离开你后，你可以根据他的一些叙述、言论等去复刻这位同事，从而便于接管他之前的工作。在这个项目的基础上，又延伸出了一个叫做“前女友 skill”的东西。

其实这两者的本质是一样的。但我认为这两个东西的实用性要小于其“整活”属性，他的用处可能不是很大。因为既然是前同事或前女友，那么由当事人去填补这个 skill 中的内容才是最好的，而不是由用户本人去做。

用户本人去制作或使用这个 skill，效果肯定不如当事人亲自提供内容更好。所以归根结底，这两个 skill 的本质还是一个记忆系统。

然后以这个记忆系统为线索，加上我最近接触到的一些东西，让我产生了很多的遐想，或者说让我很兴奋。

比如：
1. GitHub 上的一个 Mirofish 项目
2. 罗振宇每天在抖音上记录自己的生活
3. 翁家翌在接受播客访谈时，说的关于宿命论的一些话

AI 时代加速了万物的发展，也同样加速了人类对于世界的理解。

“个人记忆系统”是我最近对 AI 的一个比较新的认知，我认为这个系统对每一个人都至关重要。目前我有一个大体的思路，即这个系统需要从过去、现在和将来三个维度进行构建：

1. 过去
   即对过去的回忆，包括过去的几年、五年、十年，甚至是从你出生至今的所有记忆。这部分的工程量可能会非常大。
2. 现在
   要求当下的每一天都去做日记或记录，就像罗振宇那样。
3. 未来
   根据当下和过去的数据，结合目前的时代趋势，对未来的个人现状和发展做预测与评估。

这其中就用到了我上面提到的 Mirofish 项目。

这个个人记忆系统，目前我只是提出了一个大概的架子，中间肯定还有很多细节需要完善。比如说过去的这些回忆如何存储、具体回忆多长时间，以及当下如何做记录，还有未来如何做预测和评估，这些都需要去细化。

但是对于“现在”这个维度，我有一个大概的想法，即它是由几个 skill 组成的：

1. 日常规划 skill
   早上我会调用它来写一下今天的规划。
2. 健康管理 skill
   中间我可能会用到它去做一些运动，并记录下运动的状态、时间等。
3. 学习类 skill
   白天我会用它来协助我做一些学习记录。
4. 记录类 skill
   晚上我会调用它来记录这一天做了什么、干了什么事。

当然，晚上我还可以再次调用学习类 skill，对当天学习的内容做一个复盘。这就是我对“现在”维度的一些理解。

至于我为什么要提到 GitHub 上的 Mirofish 这个项目，是因为它原本是用来做舆情预测分析的。

举个例子：
1. 当前社会发生了一个热点事件
2. 事件过去 10 天后，我可以通过这个项目收集这 10 天的信息
3. 项目在做出分析后会进行预测，看看未来几天可能会发生什么

我觉得这个项目完全可以改造成个人记忆系统中的一个“未来维度”。它能够根据个人的历史信息进行学习，进而去预测某些事情要不要做，以及做了之后会发生什么样的结果。

然后我还想聊一下最近的几个概念：

1. Agent 协作
2. Harness
3. CLI

其实我觉得这三个概念相对于 skill 或者 vibe coding 来说，是比较专业的概念。

如果我想深挖这三个概念，一定会“陷进去”。注意，我说“陷进去”并不是贬义词，而是指如果想把这些东西研究透，会比较耗神费精力。

先说第一个概念，Agent 协作。

其实我觉得 Agent 协作这个事情，在 ClaudeCode 中已经是一个存在的概念了。例如，我可以在 ClaudeCode 中开启子代理，每个子代理可以并行执行任务。后来 ClaudeCode 升级了一个叫 Agents Team 的功能，之前的子代理都是各自完成任务后向用户提交成果，但现在子代理之间可以相互交流，沟通后再将结果交给用户。

再说第二个概念，Harness。
这个词的字面意思是“马具”，引申一下就是“驾驭”的意思。驾驭的话，到底是谁驾驭谁呢？是人驾驭 Agent，还是 Agent 之间的相互驾驭？

这让我想起 GitHub 上一个比较火的项目，叫“三省六部制”。它把中国古代的政治制度应用到 Agent 管理上，其实就已经带有一种“驾驭”的意思。

目前我对 AI Agent 的理解还比较表层，没有深入下去，仅仅停留在会用自然语言命令，以及了解几个 GitHub 项目的程度。但我认为它的内部底层才是最值得学习的东西。

我之前了解过一位博主展示的项目，是他日常用 AI 干活的示例。他在电脑上安装了三个 AI CLI 工具，分别是 ClaudeCode、Gemini 和 CodeX：
1. 他将 ClaudeCode 作为“大脑”
2. 让另外两个 CLI 作为执行助手
3. 这三个 CLI 之间可以相互通信

这种方案是我比较向往的。但在 Windows 系统上实现起来比较麻烦，需要开双系统或虚拟机，我觉得太折腾就没有做下去。但这确实是我之后努力的一个方向，我认为这才是真正的 Agent 协作。

最后聊聊 CLI。
CLI 其实就是电脑的终端命令窗口。现在很多软件已经开放了 CLI 接口，比如飞书。开放接口后，用户就可以通过 ClaudeCode 去调用并研究飞书里的文档等。

也就是说，CLI 过去是给人看的，但现在它更倾向于给 AI 看。之前 GitHub 上也有像 OpenClaw 这样的项目，目的也是让更多的软件能够方便地被 AI 调用。
